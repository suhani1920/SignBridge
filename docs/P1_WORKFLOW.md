# P1 Video Data Pipeline — Teammate Workflow & Handoff Guide

> **Document purpose:** A beginner-friendly, practical guide explaining how the P1 data preparation pipeline works, where files go, what commands to run, what has already been verified on real data, and what remains to be done.
> **Scope:** P1 data preparation (`isl/`), the P1-to-P2 export bridge (`isl/export_p2.py`), and downstream smoke testing.

---

## 1. What P1 Does and How the Pipeline Works

SignBridge is an Indian Sign Language (ISL) translator. Before machine learning models can learn signs, raw video recordings need to be converted into consistent, clean numerical measurements (3D hand landmark coordinates). That is the role of **P1**.

The end-to-end P1 flow works in sequential stages:

```
Raw Video Clip (.mp4, .mov, etc.)
  │
  ▼ [MediaPipe Hands extraction]
21 3D Hand Landmarks per Frame (x, y, z)
  │
  ▼ [Coordinate Normalization: Wrist-origin, Palm scale, Y-axis rotation]
Normalized Landmarks Sequence
  │
  ▼ [Serialization]
P1 Output: Compressed .npz Archive + Row in isl/metadata.csv
  │
  ▼ [isl/export_p2.py Bridge]
P2 Output: PoseDatabase Archive in data/pose_db/ for Recognition & Evaluation
```

### Stage Details:
1. **Video Ingestion:** P1 scans `isl/raw_videos/<gloss>/` for video clips (`.mp4`, `.mov`, `.avi`, `.webm`). The subfolder name is automatically treated as the sign label (the *gloss*).
2. **MediaPipe Landmark Extraction (`isl/extract.py`):** For each video frame, MediaPipe Hands identifies 21 key landmarks on the hand (wrist, knuckles, fingertips). Frames where no hand is detected are omitted, and clips with fewer than 5 valid hand frames are rejected.
3. **Normalization (`isl/normalize.py`):** Raw pixel positions vary depending on where a signer stands or how close they are to the camera. P1 standardizes coordinates per frame:
   - **Wrist Translation:** Landmark 0 (wrist) is shifted to `(0, 0, 0)`.
   - **Palm Scaling:** All coordinates are divided by the distance between the wrist (landmark 0) and middle knuckle (landmark 9). This ensures hand size is consistent regardless of camera distance.
   - **Y-Axis Alignment:** Rotates the hand in the XY plane so the middle fingertip (landmark 12) points straight up toward `+Y`.
4. **P1 Archive Serialization (`isl/schema.py` & `isl/pipeline.py`):** Saves the normalized clip as a compressed archive (`.npz`) containing:
   - `pose_seq`: `(T, 21, 3)` array of normalized coordinates across `T` detected frames.
   - `vec`: `(252,)` statistical summary (mean, std, min, max across time).
   - `flat_vec`: `(1890,)` sequence linearly resampled to exactly 30 frames and flattened.
   - `gloss`: scalar string label.
5. **Metadata Indexing (`isl/metadata.py`):** Atomically updates `isl/metadata.csv` with file paths and detected frame counts. Rows are uniquely keyed by `(gloss, sample_id)`, and manual annotations in the `meaning` column are preserved on re-runs.
6. **P2 Export Bridge (`isl/export_p2.py`):** Converts P1 archives into the format required by P2's matcher and evaluation tools.

## 2. Directory Layout: Where Input Videos and Outputs Go

All video files and generated data are kept outside Git tracking via `.gitignore`.

| Purpose | Path | Description |
|---|---|---|
| **Raw Input Videos** | `isl/raw_videos/<gloss>/<sample_id>.<ext>` | Where teammates place videos. Subfolder name = sign label (e.g., `isl/raw_videos/hello/clip1.mp4`). |
| **P1 Extracted Archives** | `isl/extracted/<gloss>/<sample_id>.npz` | Normalized `.npz` feature files generated by the P1 pipeline. |
| **Dataset Catalog** | `isl/metadata.csv` | CSV tracking processed samples, paths, frame counts, and glosses. |
| **P2 Pose Database** | `data/pose_db/<gloss>__<sample_id>.npz` | Resampled 32-frame archives adapted for P2 models and evaluators. |

## 3. Teammate Command Guide

Run all commands from the repository root after activating your virtual environment.

### Step 3.1: Environment Setup
We use Python 3.12 with pinned dependencies (specifically `mediapipe==0.10.21`, which preserves the `mp.solutions.hands` API).

```bash
# Check Python 3.12 availability
python3.12 --version

# Create virtual environment .venv312
python3.12 -m venv .venv312

# Activate the environment
source .venv312/bin/activate        # On macOS / Linux
# .venv312\Scripts\activate         # On Windows

# Install required dependencies
pip install -r docs/requirements.txt
```

### Step 3.2: Run Unit Tests
Verifies schema constraints, normalization mathematics, metadata handling, and feature calculations using synthetic arrays (no video files needed).

```bash
# Run P1 feature tests
pytest tests/test_features.py -v

# Run the complete test suite (P1 + P2 tests)
pytest -q
```

### Step 3.3: Extract a Single Video (Trial Run)
Useful when adding a new video clip and checking extraction without processing the whole dataset.

```bash
python -m isl.pipeline --video isl/raw_videos/hello/<video_filename>.mp4
```
*What it does:* Checks file placement, extracts landmarks with MediaPipe, normalizes coordinates, writes `isl/extracted/hello/<sample_id>.npz`, and updates `isl/metadata.csv`.

### Step 3.4: Run Full Batch Extraction
Scans all label subfolders in `isl/raw_videos/` and processes any new or updated video clips.

```bash
python -m isl.pipeline
```
*What it does:* Processes every video clip. If an output `.npz` file already exists and is newer than the source video, it skips it automatically, saving time on re-runs.

### Step 3.5: Export P1 Data to P2 Format
Converts P1 archives into P2 `PoseDatabase` format.

```bash
python -m isl.export_p2 --src isl/extracted --dst data/pose_db
```
*What it does:* Reads P1 `.npz` files, maps single-hand data into hand slot 0 of P2's two-hand schema, resamples to 32 frames, generates the 630-dimensional summary vector, and writes `data/pose_db/<gloss>__<sample_id>.npz` with `align_y=True`.

### Step 3.6: Run the Downstream Evaluator
Runs leave-one-out cross-validation (LOOCV) using cosine similarity and DTW fallback.

```bash
python -m backend.scripts.evaluate --data-dir data/pose_db
```
*What it does:* Iterates through each sample in `data/pose_db/`, holds it out as a query, compares it against the rest of the database, and reports top-1 and top-3 accuracy.

## 4. The One-Hand MVP Limitation & P1-to-P2 Bridge

### The One-Hand MVP Limitation
- **Single-Hand Tracking:** P1 currently runs MediaPipe with `max_num_hands=1`.
- **Indian Sign Language Reality:** Many ISL signs are bimanual (requiring both hands). In the current MVP, only one-handed signs or the dominant hand in two-handed signs are captured. If two hands appear in frame, MediaPipe may switch between hands across frames.
- **Spatial Position Stripped:** Because landmarks are translated to landmark 0 (wrist at origin), global movement across the camera frame and position relative to the face/torso are normalized out.

### The P1-to-P2 Bridge (`isl/export_p2.py`)
P2's architecture was designed around a two-hand layout: `(32, 2, 21, 3)` (time, hands, landmarks, coordinates). To make P1's single-hand output work seamlessly with P2:
- P1 single-hand landmarks `(T, 21, 3)` are inserted into **slot 0** (`[:, 0, :, :]`).
- **Slot 1** is zeroed out, with `mask[:, 1] = False`.
- Sequences are interpolated to exactly `SEQ_LEN = 32` frames.
- `align_y=True` is recorded in the archive, signaling downstream recognition modules that hand rotation normalization has been applied.

## 6. Why 100% on Hello-Only Data Is Not Proof of Multi-Class Accuracy

It is vital not to misinterpret the 100% LOOCV score.

- In a single-class dataset containing only `hello` videos, **every candidate retrieved from the database is also `hello`**. Even a dummy model that randomly guesses or always outputs `hello` would score 100%.
- **What the test actually proved:** The 100% score proves that the end-to-end machinery works without crashing: video reading, landmark extraction, coordinate normalization, file serialization, bridge conversion, matrix shapes, database indexing, and the LOOCV evaluation harness all function properly together.
- **What the test did not prove:** It does **not** prove accuracy, class discrimination, or generalization. We do not yet know how well the model distinguishes `hello` from `thankyou`, `yes`, or any other sign.

## 7. What Remains to Test and Next Steps

To move beyond the single-class sanity test, teammates can take on the following tasks:

1. **Add Other Sign Classes (Multi-Class Data):**
   - Create new gloss subfolders under `isl/raw_videos/` (e.g. `isl/raw_videos/thankyou/`, `isl/raw_videos/yes/`).
   - Add video recordings for these new classes and run batch extraction.
2. **Multi-Class Recognition Evaluation:**
   - Run `isl.export_p2` and `backend.scripts.evaluate` on the multi-class dataset.
   - Check the confusion matrix and distance separation to verify whether cosine distance and DTW can reliably tell classes apart.
3. **Two-Hand (Bimanual) Support:**
   - For signs requiring two hands, investigate extending P1 extraction to `max_num_hands=2` and populating both hand slots (slot 0 and slot 1) rather than just slot 0.
4. **Curating the `meaning` Column:**
   - Populate natural English text translations in the `meaning` column of `isl/metadata.csv` (e.g., changing empty strings to `"Hello"`). The pipeline is configured to preserve these manual edits during re-runs.
5. **Video Source Variation Analysis:**
   - Examine performance differences between clips from different sources (e.g. INCLUDE vs ISL500), signers, resolutions, and frame rates.
